# Growith — Contexto para Claude Code

## Qué es este proyecto
Growith es una SaaS de gestión para e-commerce argentino, construida en React (JSX en un solo archivo).
Actualmente en uso real por Soluna Biolight (anteojos blue light blocker).

## Stack
- **Frontend:** React JSX (`src/App.jsx`) — todo en un solo archivo (~13.500 líneas)
- **Backend:** Serverless functions en `/api/` (Vercel)
- **DB:** Firebase Firestore + Auth
- **Deploy:** Vercel (proyecto "growith")
- **Repo:** `https://github.com/SolunaBiolight/soluna-gestion`
- **Prod:** `https://soluna-gestion.vercel.app`

**Matcheo de sucursales Andreani** (bloque `GH_SUC_MATCH_BEGIN…END` en App.jsx, funciones puras `ghNrmSuc`, `ghDirParse`, `ghMismaCalle`, `ghPuntoDeOrden`, `ghConflictoPunto`, `ghCoincidePunto`, `ghMatchOficial`, `ghMatchSucursal`; wrappers de AppEnvios `matchSucursalOficial`/`conflictoSucursal`/`coincideSucursal`/`findAndreaniSucursal`). Regla dura: el auto-match SILENCIOSO solo acepta calle+número iguales o nombre del punto, y se veta ante contradicción grave (otro número en la misma calle, CABA vs GBA, otro CP con otra localidad, > 4 km con ancla geocodificada); nunca "la única del CP" ni "la más cercana". Sin número de puerta no se adivina contra el template. En el lote por API una fila con contradicción grave NO se emite salvo que se haya confirmado a mano en el modal (`conflictoOk`). Excepción (23/sep/2026): sucursal OFICIAL nombrada por calle en el desplegable ("ROSARIO (AV SAN MARTIN)", sin número) → `ghSucursalNombradaUnica(sucursales,tplStr,punto)`: si el punto del pedido tiene número, esa calle y esa localidad y es la ÚNICA entrada "LOCALIDAD (…)" con esa calle, la verificación la da por buena (no aplica a HOP ni a entradas con números). Tests: `node scripts/suc_match_test.cjs` (sin dependencias; usa el desplegable real en `scripts/fixtures/tpl_sucursales.txt`, regenerarlo con `node scripts/tpl_fixture.cjs` cuando cambie el xlsx) — correrlos antes de tocar cualquier función del bloque. Hechos del desplegable del Excel (15/sep/2026): 3.468 entradas, 95 % puntos HOP, nombres RECORTADOS a 50 caracteres (208 HOP quedan sin número, ej. "PUNTO ANDREANI HOP AVENIDA DOCTOR RICARDO BALBÍN" ×9 idénticas) y abreviaturas ("AV B MITRE", "AV PTE H YRIGOYEN", "ALTE G BROWN"); `ghMatchSucursal` acepta la entrada recortada solo si es el comienzo literal de "PUNTO ANDREANI HOP <calle> <número>" del pedido y es única, expande abreviaturas (`GH_SUC_ABREV`) y conserva calles de puras palabras cortas ("Santa Fe", `GH_SUC_VIA`/`GH_SUC_TITULO`). Puntos HOP y la API (resuelto 16/sep/2026): los LISTADOS (`/v2/sucursales`, `?canal=B2C|HOP`, `/v2/puntos-de-tercero`) traen UN solo HOP para nuestra cuenta, pero `GET /v2/sucursales/{id}` SÍ resuelve cualquier punto HOP (id = 10000 + número del punto, canal B2C, tipo DEALER, código HOPnnnn, dirección completa, CP, coordenadas, horario; responde incluso sin credenciales). `api/_hop.js` mantiene el índice propio: foto inicial `api/_hop_index.json` (2.651 puntos) + cron `/api/andreani?action=hop_index_cron` (cada hora, barre ids 10000..20999 por tandas de 1.500 con cursor en `andreani_config/hop_idx_meta`; al cerrar la vuelta reemplaza los shards `hop_idx_{n}`; Admin > Sistema lo lista y la sonda de Andreani tiene el botón "Índice HOP" = `admin_hop_index`). `sucursalesPorCp`/`sucursalesTodas` mezclan el índice DESPUÉS de sus cachés (`conHop`, oficiales primero; `sinHop` para la sucursal de ORIGEN, que nunca puede ser un HOP), así el matcheo de Envíos, el modal, el buscador global, cercanías (`suc_geo2`) y el checkout de Shopify ven los HOP como una sucursal más (`hop:true`). Al emitir a un HOP, `emitir` lo confirma EN VIVO con `/v2/sucursales/{id}` antes de debitar (fail-closed; 404 → `hop_inactivo`). `ghEsHop(o)` ya no excluye nada. El sitio público `www.andreani.com/api/sucursales/byCoordenadas?lat&lng` también lista HOP (30 más cercanos, con `puntoDeTerceroId` = mismo id) — solo referencia.

## Design System (DS)
Tokens centralizados definidos en `const DS`:
```js
DS.sp    // spacing: xs(4) sm(8) md(12) lg(16) xl(20) 2xl(24) 3xl(32) 4xl(48)
DS.r     // border-radius: sm(6) md(8) lg(10) xl(14) 2xl(16) full(9999)
DS.font  // font-size: xs(10) sm(11) md(12) base(13) lg(14) xl(16) 2xl(20) 3xl(26) 4xl(34)
DS.w     // font-weight: regular(400) medium(500) semibold(600) bold(700) black(800)
DS.shadow // sm md lg xl
DS.ease  // cubic-bezier(0.4, 0, 0.2, 1)
```

Temas: `const DARK` y `const LIGHT` — el usuario elige, se guarda en localStorage.
El tema activo se pasa como prop `T` a todos los componentes.

Componentes base reusables (usar siempre en código nuevo):
- `<Card T={T} padding="lg" hoverable onClick={fn}>` — contenedor estándar
- `<KPI T={T} label="" value="" sub="" icon="" color="" onClick={fn}>` — métrica
- `<Btn T={T} variant="primary|secondary|ghost|danger|success" size="sm|md|lg">` — botón React
- `<DSBadge T={T} color={T.red} size="sm|md">` — badge/chip
- `<DSEmpty T={T} icon="" title="" subtitle="" action={<Btn/>}>` — estado vacío
- `<DSToggle T={T} active={bool} onToggle={fn}>` — switch toggle
- `<ModalCloseBtn T={T} onClick={fn} disabled={bool}>` — botón ✕ estándar de modales

### Sistema de botones — dos formas equivalentes
Ambas producen el mismo resultado visual. Usá la que más te convenga en cada contexto:
```js
// Forma React (para código nuevo o cuando ya usás JSX):
<Btn T={T} variant="primary">Acción</Btn>
<Btn T={T} variant="secondary">Cancelar</Btn>
<Btn T={T} variant="danger">Eliminar</Btn>

// Forma style-object (legacy, sigue funcionando igual):
<button style={{...BtnPrimary(T)}}>Acción</button>
<button style={{...BtnSecondary(T)}}>Cancelar</button>
<button style={{...BtnDanger(T)}}>Eliminar</button>
```
**No mezclar estilos de un sistema con el otro** (ej: no hacer `<Btn style={{...BtnPrimary(T)}}>`).

## Reglas de trabajo — MUY IMPORTANTE

### Antes de cualquier cambio
1. Leer los archivos relevantes completos antes de tocar nada
2. Verificar sintaxis JSX con `npx babel --presets @babel/preset-react` o similar

- **Siempre** usar los componentes base (`Card`, `Btn`, `KPI`, `DSBadge`, `DSEmpty`)
- Fuente: `'Inter',system-ui,sans-serif` en todos lados
- `fontFamily` siempre explícito en botones y inputs
